# 가챠 포지 퀘스트 확장 (Gacha Forge Quest Extension)

**버전:** v0.3.11 — 앱 내부 상단바 아이콘 / 수동 기록 베타
가챠 포지 전용 독립 개인 확장. 공식 Gacha Forge 파일 및 한글화 확장 파일을 수정하지 않는다.

## 기능
- 가챠 포지 앱 상단바 전체 화면 버튼 옆 `📜` 아이콘 → 퀘스트 / 자산 / 소지품 / 기록 / 설정
- 월드 직접 등록, 전환, 분리 저장
- 일일/주간/의뢰/업적 퀘스트 직접 등록, 진행도 변경, 완료 표시
- 월드별 사용자 정의 자산 필드 및 소지품 수량 직접 편집
- 최근 변경 기록 및 JSON 백업 내보내기/가져오기

## 중요 제한
- 세계 선택은 수동. 게임 내부 세계 ID에 연결된 자동 동기화 없음.
- 퀘스트 반복 초기화, AI 의뢰 생성, 스토리 자동 분석, 전투/가챠 이벤트 자동 수집 없음.
- 게임 재화 지급 없음. 보상 텍스트는 메모에만 기록됨.
- localStorage 저장: 브라우저/도메인별이며 기기 간 자동 동기화되지 않는다.
- 공식 1.8.12의 가챠 포지 Shadow DOM에서 `.gf-fs-bar.icon-button` 옆에 아이콘을 삽입한다. 실제 실행 테스트는 아직 하지 않았다.
- 팝업은 브라우저 최상위 레이어(dialog)에 표시하도록 설계했으며 실제 전체화면 동작은 미검증이다.

## 설치
ZIP의 manifest.json 및 extension.js가 압축 루트에 있도록 업로드. 클라이언트 확장 실행 허용 후 가챠 포지 진입. 상단바 전체 화면 버튼 옆 `📜` 아이콘 표시를 확인.

## 검증
manifest JSON 문법, JS 구문 검사, ZIP 구조 검사 수행. 실기기 실행/게임 이벤트 호환 테스트 미실시.

## v0.1.8 변경 사항

- 챕터 목록 버튼은 아직 별도의 읽기 요청을 보내며 환경에 따라 403이 발생할 수 있습니다. 과거 스토리 전체 분석 기능은 미구현입니다.
- 기존 퀘스트·자산·소지품 및 로컬 저장 데이터 보존. JavaScript 구문 검사 통과.

- 기존 로컬 스토리지와 수동 기능을 보존합니다. GitHub JS 구문 검사만 완료했고 실제 마리나라 실행 테스트는 미실시입니다.

## v0.2.1 AI 연결 선택 준비

- 분석 실행 방식(수동/자동), 분석 범위(챕터/장면) 설정을 로컬로 저장합니다.
- **주의: 선택과 저장만 구현**. 선택한 모델을 호출해 분석하거나 기존 스토리를 자동 분석·적용하는 기능은 아직 없습니다. `가챠 포지 기본 연결`의 실제 모델 ID 해석과 모델 호출은 추후 공식 지원 경로를 확인한 뒤 구현해야 합니다.
- 연결 목록 API 접근이 거부될 경우 화면에 오류를 표시합니다. 서버 인증 우회는 하지 않습니다.
- 기존 데이터 구조의 필드는 유지. 실제 마리나라 실행 테스트는 수행하지 않았고 JavaScript 문법 검사만 통과했습니다.

## v0.2.2 AI 분석 검토 파이프라인
- 기록 탭: 저장된 챕터·장면으로 AI 분석 지침 복사, AI가 반환한 JSON 배열 가져오기, 원문 일치 검사, 중복 제거, 후보별 승인·제외.
- 분석 응답 스키마: `category`(quest/asset/item), `name`, `status`(completed/active/confirmed/uncertain), `evidence`, `source`, `amount`, `unit`.
- 근거 문구가 저장된 실제 챕터·장면에 포함되지 않으면 수입하지 않음. 불확실한 사건은 수동 확인 필요.
- 승인된 의뢰는 사용자 정의 의뢰로 추가; 아이템은 수령이 확정되고 수량이 있는 경우에만 기록; 자산 거래는 잔액을 임의로 조작하지 않고 이력으로 기록.
- **실제 선택 AI 연결의 모델 호출은 미구현**: 공식 개인 확장 API에 범용 텍스트 생성 브로커가 없어 연결 ID만으로 호출 불가. 자동 호출에는 별도 공식 capability-pack/서버 연동 필요.
- 모델 목록과 선택 설정은 유지. 기존 데이터 보존. JavaScript 구문 검사 외 실기기 검증은 미실시.

## v0.2.3 실험적 서버 브리지
- `bridge/server.mjs`, `bridge/manifest.json`: 서버 측 모델 선택 및 채팅 완성 기반 구조화 추론 시도
- 기록 탭 `AI 분석 실행 (서버 브리지)` 버튼: 선택한 연결 ID와 이미 수집한 스토리만 전달. 요금 동의 확인 후 POST 요청
- 응답을 기존 원문과 대조하여 검토 목록에 넣으며 원본 게임 저장 데이터는 수정하지 않습니다.
- **중요**: 브리지는 실험적 소스만 커밋됐습니다. 서버에 아직 설치되지 않았으며 패키지 등록 유효성, 실제 라우트 URL, 권한 정책, 엔진 2.5.0 실행은 검증되지 않았습니다. 버튼은 현재 실패할 수 있습니다.
- 엔진 파일/기존 Gacha Forge 패키지는 수정하지 않았습니다. 정상 설치 확인 전 자동 분석 기능은 활성화하지 마세요.

## v0.2.4 개인 확장 직접 AI 호출
- 기억 서재 v0.10.20에서 확인한 `POST /api/generate/raw` (host.apiFetch가 있으면 우선 사용) 방식으로 전환했습니다. 별도 브리지 설치가 필요하지 않습니다.
- 설정에서 선택한 연결 ID를 사용해 현재 월드의 수집된 챕터 줄거리·스토리 문장을 분석합니다. 사용자 승인 후에만 서버 AI 호출하며 사용 요금이 발생할 수 있습니다.
- AI 응답을 구조화된 JSON 후보로 파싱하고 실제 저장된 원문과 대조하여 검토 목록에 적재합니다. 승인하지 않은 상태에서 게임 자산/소지품은 변경하지 않습니다.

- JS 구문 검사 통과. 실제 엔진 2.5.0에서 모델별 추론 성공 여부, JSON 호환성, 확장 동시 실행은 미검증입니다.

## v0.3.7 AI 기반 범용 퀘스트 통합
- 사건 추출이 끝나면 AI 호출을 1회 추가해, 같은 임무에 속한 퀘스트 후보를 하나의 상위 퀘스트와 세부 목표로 묶습니다. 특정 챕터·장소 규칙 없이 모든 월드에서 작동합니다.
- 이전 분석에서 남아 있던 미승인 퀘스트 후보와 이미 등록된 퀘스트도 함께 비교합니다. 기존 퀘스트의 이어지는 장면이면 새 퀘스트를 만들지 않고 '기존 퀘스트 갱신' 후보로 표시합니다.
- 갱신 후보를 승인하면 기존 퀘스트에 세부 목표·완료 상태·보상만 더합니다. 확정 보상이 생기면 아직 지급되지 않은 기본 명성 제안은 제거합니다.
- AI는 짧은 ID로 묶음만 제안하고, 확장은 ID 유효성·중복 배정·갱신 대상 존재 여부를 검사합니다. 원문 근거는 기존 후보의 것을 그대로 사용하며, 통합이 실패하면 개별 후보로 유지합니다.
- 완료 판정은 묶인 후보가 모두 완료이거나, AI가 제시한 모든 세부 목표가 완료로 확인될 때만 인정합니다.
- 퀘스트 카드의 세부 목표를 눌러 완료·미완료를 직접 바꿀 수 있습니다(변경 기록에 남습니다).
- JSON 가져오기에서도 AI 연결이 선택되어 있으면 같은 통합을 수행합니다.
- 설정 탭의 현재 월드 이름을 내부 키 대신 표시 이름으로 보여 줍니다.
- 기존 월드 전용 보정(v0.3.4 규칙)은 통합 전에 그대로 적용됩니다.
- 저장 데이터에 `stepDone`(퀘스트), `questStepDone`·`updateOf`·`mergedCount`(검토 후보) 필드만 추가했습니다. 타이머·감시 주기 변경 없음.
- `tests/ui.smoke.js`: 가상 브라우저에서 패널 열기, 세부 목표 전환, 기존 퀘스트 갱신 승인을 확인합니다. 실제 마리나라 환경 검증은 아직 수행하지 않았습니다.

## v0.3.8 맥락 연결형 거래·보상 관리
- 각 분석 묶음에 앞선 묶음에서 찾은 약속·거래·수령 예정 물품과 기존 거래 원장을 짧은 ID 목록(최대 약 2,000자)으로 함께 전달합니다. AI는 새 사건이 그 후속(지급 실행, 입금, 물품 수령 등)이면 연결 ID를 붙입니다.
- 확장은 연결을 그대로 믿지 않고 검증합니다: 금액·단위가 다르거나, 유형이 다르거나, 상태가 역행하면(입금 → 지급 예정 등) 연결을 거부하고 별개 항목으로 남깁니다. 연결된 후보에는 '이전 기록 연결: ○○ (지급 예정 → 입금 확인)'이 표시됩니다.
- 연결된 후보를 승인하면 새 거래를 만들지 않고 같은 거래의 상태 이력에 추가합니다. 승인 순서가 뒤바뀌어도(입금 장면을 먼저 승인) 거래 상태가 되돌아가지 않습니다.
- 같은 계약이나 장면에서 금액들의 합이 다른 금액과 정확히 일치하면 그 금액들을 총액의 구성 금액으로 표시합니다. 구성 금액은 승인해도 원장에 별도 수입으로 기록하지 않습니다. 특정 금액에 맞춘 규칙이 아니므로 모든 월드에 적용됩니다.
- 퀘스트의 금전 보상은 같은 금액의 거래가 원장에 정확히 하나 있으면 자동으로 연결되며, 보상 표시가 원장의 실제 상태(지급 예정·입금 확인 등)를 따릅니다. 연결되지 않은 보상은 퀘스트 카드의 [원장에 기록] 버튼으로 기록할 수 있고, 이후 같은 금액의 계약 후보를 승인하면 그 거래에 합쳐집니다.
- 수령 예정 물품: '내일 이 시간에 수령'처럼 아직 받지 않은 물품은 소지품 탭의 '수령 예정'으로 등록되며 보유품과 스토리 문맥에서는 제외됩니다. 이후 연결된 수령 장면을 승인하거나 [수령 확인]을 누르면 보유품으로 전환됩니다.
- 저장 데이터에 `chainKeys`·`origin`(거래), `txId`(퀘스트 보상), `state`·`chainKey`·`timing`·`value`(소지품)만 추가했습니다. 타이머·감시 주기 변경 없음.
- `tests/ui.flow.js`: 가짜 AI 연결로 두 묶음 분석 → 맥락 연결 → 일괄 승인까지 확인합니다. 실제 마리나라 환경 검증은 아직 수행하지 않았습니다.

## v0.3.9 챕터 단위 분석
- 가챠 포지가 스토리를 챕터 단위로 생성하므로, AI 분석도 챕터 하나(줄거리 + 장면)를 한 회차로 보냅니다. 서로 다른 챕터가 한 회차에 섞이지 않습니다.
- 한 회차에 담기에 너무 긴 챕터(본문 약 15,000자 초과)만 순서대로 나눕니다(예: 챕터 3 1/2부, 2/2부).
- 앞 챕터에서 찾은 약속·거래·수령 예정 물품은 다음 챕터 회차에 이전 맥락으로 전달됩니다.
- 실행 확인 창과 결과 알림에 챕터 기준 회차를 표시하며, 실패 시 어느 챕터가 실패했는지 보여 줍니다.
- 챕터 수만큼 AI를 호출하므로 챕터가 많으면 호출 횟수가 늘 수 있습니다. 전체 제한 시간은 최대 30분입니다.

## v0.3.10 보상 연결 및 물품·현금 구분
- 'N원 상당의 건틀릿'처럼 물품의 가치로 적힌 금액은 받을 돈이 아니라 물품으로 분류합니다. 받기 전이면 수령 예정 물품이 되고, 가치는 '물품 가치 (현금 아님)'으로만 표시합니다.
- 퀘스트 통합 단계에서 같은 임무의 대가인 수당·보수·물품·자격 후보를 퀘스트 보상으로 연결합니다. 한 보상 후보는 한 퀘스트에만 연결되며, 보상이 연결되면 기본 명성 제안은 붙지 않습니다.
- 연결된 보상은 해당 후보를 승인할 때 원장 거래·소지품과 이어져, 퀘스트 카드에 실제 상태(입금 확인, 수령 예정, 보유 등)로 표시됩니다.
- 목표 문장만 반복하는 단일 세부 목표는 표시하지 않습니다.
- 퀘스트 후보에는 '지급·수령 시점' 대신 '기한·시점'으로 표시합니다. 가정 조건(중도 철수 시 등)은 시점으로 쓰지 않도록 분석 지침을 보강했습니다.
- 게임 기록상 클리어된 챕터의 진행 중 퀘스트에는 완료 여부 확인을 권하는 참고 문구를 표시합니다(상태를 자동으로 바꾸지 않습니다).
- 자격 승인 시 기존 '보유 자격' 항목과 같은 자격이면(예: 물리계 정식 면허 교부 ↔ 물리계 C급 정식 면허) 새 항목을 만들지 않습니다.

## v0.3.11 비금전 보상·구매/판매·분석 범위
- **명성 수치:** 퀘스트 통합 단계에서 임무의 규모와 공적을 보고 명성 +1~5점을 사유와 함께 제안합니다(1 소규모 의뢰 ~ 5 세계관 전체에 알려질 업적). 이 제안은 확장 자체 규칙이며, 금전 보상과 함께 표시될 수 있습니다. 보상이 전혀 없을 때 붙던 기본 +1점은 기존처럼 금전 보상과 함께 붙지 않습니다. 완료 승인 시 제안 점수만큼 자산 탭의 `명성` 필드에 더합니다.
- **혜택 이용권:** '공임 50% 감면'처럼 앞으로 쓸 수 있는 할인·감면은 새 유형 '혜택'으로 분류하고, 승인하면 소지품 탭의 '혜택·이용권'에 1회권(명시된 횟수)으로 추가됩니다. [사용]을 누르면 횟수가 줄고 사용처가 기록됩니다. 이미 특정 거래에 적용된 면제는 기록만, 기한 없는 상시 혜택은 자산 탭의 '보유 혜택'으로 등록합니다. 퀘스트 보상에 연결된 혜택은 남은 횟수가 표시됩니다.
- **구매 내역:** 구매는 지출(원장)과 산 물품(소지품)을 함께 기록합니다. 아직 받지 않은 주문품은 수령 예정으로 들어갑니다.
- **판매 내역:** 판매는 대금(원장)을 기록하고 판 물품을 소지품에서 차감합니다. 대금을 현금으로 건네받은 경우는 입금으로 인정하되, '정산 완료' 표현만으로는 여전히 입금으로 보지 않습니다.
- **원장 요약:** 자산 탭 상단에 승인한 원화 거래 기준 입금 확인·지출·순변동·받을 돈 합계를 표시합니다. 소지금 필드나 게임 재화는 자동으로 바꾸지 않습니다.
- **분석 범위:** 기록 탭에서 '새로 추가·변경된 챕터만'(기본), '전체 챕터', '챕터 직접 지정(예: 4, 2-4)'을 고를 수 있습니다. 분석에 성공한 챕터는 내용 지문을 저장해, 장면이 추가되거나 바뀐 챕터만 다시 분석합니다. 사용하지 않던 설정 탭의 '분석 범위(챕터/장면)' 항목은 제거했습니다.
